# AI Coding Standard v1.0

先读取 references/GLOBAL_STANDARD.md。初始化或修改项目规范时读取 references/PROJECT_STANDARD_TEMPLATE.md；执行任务及验收时读取 references/TASK_CHECKLIST.md。

## 工作入口
- 初始化：明确目标、用户、边界、MVP、约束；调研复用；提出原型、技术选型、架构、项目规范及测试策略，重大决策交由人类确认，再制定 SPEC/PLAN/TASKS；未确认不进入复杂功能正式编码。
- 接管：只读检查代码、Git、依赖、运行方式、架构和现有文档，先报告状态、风险及建议；不擅自重构。
- 推进：读取项目规范和任务状态，确认依赖与范围，执行当前授权任务，运行验证，审查差异，更新文档并汇报；重要里程碑等待验收。
- 修复：复现、证据、根因、最小修改、回归验证；反复失败重新检验假设。
- 审查：独立检查规格、正确性、安全、兼容性、性能、测试、范围，按严重程度报告；未经授权不修改。
- 部署：核查版本、环境、构建、测试、备份、回滚和授权；上线后验证关键路径。
- 复盘：解释架构、决策、数据流、故障和经验；学习项目同步沉淀知识。

## 适配原则
四层：全局规则→项目专属规范→功能规格→任务约束。低风险小任务可简化文档与审批；重大架构、权限、数据、依赖、生产变更必须先明确方案、风险、回滚并获得确认。不要把模板当成固定技术答案。工具不可用时如实说明，不假称已操作或验证。项目规范随实践演进；重大变化需确认。
